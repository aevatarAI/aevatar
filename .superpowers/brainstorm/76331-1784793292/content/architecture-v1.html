当前 codex_exec managed_sandbox 架构

以 Aevatar 当前实现、NyxID proxy contract，以及线上 chrono-sandbox PR #8 为事实基线。

结论：是通过 NyxID 的 chrono-sandbox 执行。 主链为 Aevatar codex_exec → NyxID Proxy → chrono-sandbox → OpenSandbox/gVisor runner → Codex CLI → NyxID LLM Gateway。Aevatar 不直接创建或管理 OpenSandbox。

凭证控制面与信任边界

凭证的“生命周期事实”“秘密字节”“NyxID 外部授权事实”由不同权威源负责，执行路径只读 projection，不直读 Actor state。

Self-service API

  • GET /api/managed-codex/credential
  • POST provision / rotate
  • DELETE revoke
  • 认证用户 bearer + internal allowlist
→

Application Lifecycle

  • 用 /users/me 校验 subject
  • Garnet 分布式 mutation lease
  • 校验 chrono-sandbox + chrono-llm readiness
  • issue / rotate / revoke / compensate
→

Authoritative Writes

  • NyxID：创建 exact-scope agent key
  • Vault：只存 raw key bytes
  • Command Port：accepted-only dispatch
  • Credential GAgent：提交 Protobuf domain event
→

Projection Read Path

  • Committed state publication
  • Projection Pipeline materialization
  • ManagedCodexCredentialDocument
  • execution 只查 read model + Vault ref
Actor 是 Aevatar 生命周期事实源owner、key ID、SecretReference、service ID、status、expiry、pending cleanup；不含 raw secret。
Vault 是 raw secret 唯一持有者每次发行使用独立 deterministic ref；rotation 不覆盖当前 descriptor 指向的旧 secret。
NyxID 是外部授权事实源agent key 是否 active、exact grants、UserService policy 与 delegation JWT 均由 NyxID 决定。

仍有 mutable UserService policy 信任边界Aevatar 在 provision/rotate 时校验 forward_access_token=false，但无法把之后的 policy 变更绑定到每次执行。PR #8 会拒绝收到的 Authorization，但 broad rollout 仍由 #2899 跟踪更强的不可变/请求级保证。
短期 token 直接存在 runner env这是 ADR-0044 的明确选择，没有 sandbox Credential Vault。完全攻破 sandbox 的最坏影响是该用户最多 5 分钟的 LLM quota。
网络控制是平台级且较粗OpenSandbox create request 不声明 network policy；operations 应用 IP-level Kubernetes NetworkPolicy。因为 NyxID 在共享 CDN 后，不宣称 FQDN allow-list。
