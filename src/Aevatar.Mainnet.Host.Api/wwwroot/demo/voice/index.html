1. Host 负责 provider 配置

这个 demo 只连接当前 Mainnet Host。Voice provider 是否可用由 Host 配置和 voice readmodel 决定，页面不会声明固定上游 endpoint。

2. Agent 要有 voice module

点击“开始说话”时，demo 会自动创建或复用当前用户的 voice demo agent，并挂上 `voice_presence_openai` 模块。请求里的 NyxID bearer 只用于当前 Host 的身份认证，不会作为 provider credential 暴露给浏览器。

普通 `/ws/voice` 只从 typed `voice_attach_target` 读取目标 agent；`/ws/voice/{actorId}` 是调试直连入口，需要登录用户具备 `voice:bypass` scope 或 admin/owner 角色。

3. 调试直连

demo 会调用 `POST /api/demo/voice/bootstrap`，在当前 NyxID scope 下登记 demo agent，并把 voice route 写成 typed `voice_attach_target`。返回的 `actor_id` 与 `voice_module_name` 可用于调试直连；临时换目标 agent 时使用显式 bypass 路径。

wss://MAINNET_HOST/ws/voice/YOUR_AGENT_ACTOR_ID?voice_module_name=voice_presence_openai

4. 打开 demo

线上部署后访问当前 Mainnet Host 的：

/demo/voice

本地调试启动 Mainnet Host 后访问：

http://127.0.0.1:5080/demo/voice

浏览器会请求麦克风权限。连接成功后直接说话，agent 的音频回复会从当前页面播放。
