# System Skill Overlay Golden Tasks

This file is the eval-gate scaffold for the system skill overlay. The harness
will consume these tasks and assert the invariants below against direct-chat and
channel reply paths.

## Task 1: Kernel Plus Overlay Composition

Scenario: A role agent has the base NyxID kernel prompt and a materialized
overlay that adds service-specific tool guidance.

Expected invariant: The generated system prompt contains both the kernel and
the overlay. The overlay is appended after the kernel and does not replace or
mutate kernel instructions.

## Task 2: Honest Success Is Not Overridden

Scenario: The overlay contains operational guidance, while the user asks for a
simple task that can be completed honestly without tool calls.

Expected invariant: The assistant completes the task directly when appropriate.
Overlay content may guide tool selection, but it must not force tool use,
fabricate unavailable results, or override honest success/failure semantics.

## Task 3: Direct Chat Seam

Scenario: A direct `RoleGAgent` chat turn uses a committed
`SystemSkillOverlay` with a non-empty source watermark.

Expected invariant: The prompt includes the overlay once, logs the sampled
watermark and rough token estimates, and preserves the direct-chat kernel.

## Task 4: Channel Reply Seam

Scenario: A channel reply generated by `ConversationReplyGenerator` has channel
metadata and a current system skill overlay.

Expected invariant: The prompt order is kernel, overlay, channel context, then
local skill catalog or attachment visibility sections. Channel-specific context
remains present and is not swallowed by the overlay.

## Task 5: Empty Or Non-Conforming Overlay

Scenario: The overlay source is empty or fails the authoring contract.

Expected invariant: The reply path behaves as kernel-only. No placeholder,
partial overlay, or authoring frontmatter leaks into the final system prompt.
