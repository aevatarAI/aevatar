2. “MCP 2.0”的准确含义

这里的 “2.0” 同时指 Milestone 39 的产品简称与官方 C# SDK 2.x；wire protocol 仍用日期版本协商，Aevatar 当前目标是 2026-07-28。

Wire protocol

2026-07-28

取消协议级 session 与 initialize handshake，新增 server/discover，每个请求携带协议版本与客户端能力。

Official SDK

2.1.0

2.0.0 正式对齐 2026-07-28；2.1.0 增强 HTTP transport fallback，并可在 discover 的 HTTP 失败后回退旧 initialize。

Aevatar strategy

Discovery first

ProtocolVersion = null 交给 SDK 选择新协议，并自动兼容 2025-11-25 及更旧 peer，避免自建协议分叉。

重要变化：2026-07-28 的上游能力不只是“升级包版本”。它还引入 ttlMs/cacheScope、标准 HTTP headers、任意 JSON 的 structuredContent、MRTR input_required、subscriptions/listen 与必需的 resultType。本 milestone 只实现了其中与 Tool Client 主链直接相关的部分。

6. 审计发现并已登记的新问题

#3205
BugArchitecture

Connector timeout 没有进入 MCP negotiation

Studio 会把 timeoutMs clamp 到 100–300000ms 并持久化；MCPConnectorBuilder 构造 MCPServerConfig 时却没有设置 InitializationTimeout，所以 catalog connector 始终使用默认 30 秒。相同配置在 mcp.json 路径是正确的，形成双重语义。

最小修复：在唯一 builder 映射一次，并给 STDIO/HTTP 各留一个断言；不新增抽象。

#3206
Verification

#3197 的 canary 没有触达 MCP path

GET → invalid PUT 400 → GET 证明的是 catalog XOR 边界与部署健康，不是 discovery/list/call。关闭证据缺少 MCP server、tool call、run/correlation identity、typed success receipt 和对应协议日志。

最小补证：用一个安全、确定性的 allowlisted tool，经 nyxid proxy request aevatar 调用一次，记录 exact identity、terminal receipt 与 read-only Kubernetes correlation。

生产复核限制：本轮没有绕过安全边界重跑生产调用。当前 NyxID CLI session 已过期；本机 scoped kube ingress 返回 403。该限制不影响上述证据判断，因为 #3197 自身的持久关闭评论已经完整列出它实际执行的 GET/PUT/GET 序列。
